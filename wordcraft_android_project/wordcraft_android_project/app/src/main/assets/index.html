WordCraft Open-Source Document Engine (ECMA-376 .docx) ArtCraft / Pure Rust Architecture

The Open Studio Handbook

Willkommen in WordCraft für Android — dem vollständigen, quelloffenen Nachbau von storytold/wordcraft. Diese Version vereint die 9 originalen Ribbon-Registerkarten, das schnelle Seitenlayout, Track Changes, Randkommentare und den nativen .docx-Import/Export mit einer für Android-Touchscreens optimierten Oberfläche.

1. Architektur & Dateiformate

Genau wie das Desktop-Vorbild liest und schreibt diese App echte Microsoft Word (.docx)-Dateien direkt lokal auf deinem Gerät (ohne Cloud-Zwang) sowie Markdown (.md), HTML, LaTeX (.tex) und Klartext (.txt). Über den Button 🤖 APK Build oben rechts erhältst du außerdem die korrigierte GitHub-Actions-Pipeline für dein Repository FloodedCode/wordandroid.

2. Überarbeitungsmodus & Kommentare

Im Reiter Überprüfen (Review) ist die Änderungsnachverfolgung direkt integriert: Wenn Track Changes aktiv ist, werden neue Eingaben als nachverfolgte Einfügung und gelöschte Passagen als durchgestrichene Löschung markiert. Außerdem können Textstellen mit Randkommentaren versehen werden.

„Paragraph layout is cached: typing in a 188-page document re-lays it out in about 1.4 ms, with pages rendered on demand.“ — WordCraft Technical Spec (Thomas, 2026)

🤖 Android APK Build & GitHub Actions Setup (FloodedCode/wordandroid)

Warum ist dein GitHub-Actions-Build in FloodedCode/wordandroid nach 4–5 Sekunden fehlgeschlagen?
Das originale Repository storytold/wordcraft ist ein reines Desktop-/Wasm-Rust-Workspace (egui + wgpu) ohne android/-Gradle-Ordner, ohne gradlew und ohne android_activity-Entry-Point. Wenn eine Standard-GitHub-Action nach ./gradlew assembleRelease sucht, bricht sie sofort nach ~4 Sekunden ab.

Lösung (2 funktionierende Wege für eine 1:1 Android-APK):

Option A (Sofort-Fix für GitHub Actions): Diese .github/workflows/build-apk.yml erzeugt das fehlende Android-Gradle-Gerüst automatisch im Runner, bettet den WebAssembly-Build von storytold/wordcraft (oder diese mobile App) ein und baut + signiert eine universelle Android-APK:

Option B (Nativer Rust-Build über cargo-apk / winit für storytold/wordcraft): Falls du den Rust-Code direkt nach aarch64-linux-android kompilieren willst, ergänze in crates/wordcraft/Cargo.toml:
[lib] name = "wordcraft_android" crate-type = ["cdylib"] [target.'cfg(target_os = "android")'.dependencies] android-activity = { version = "0.6", features = ["native-activity"] } eframe = { version = "0.29", default-features = false, features = ["wgpu", "android-native-activity"] } // In src/lib.rs: #[cfg(target_os = "android")] #[no_mangle] fn android_main(app: android_activity::AndroidApp) { std::env::set_var("WGPU_BACKEND", "vulkan,gles"); let mut options = eframe::NativeOptions::default(); options.android_app = Some(app); let _ = eframe::run_native( "WordCraft", options, Box::new(|cc| Ok(Box::new( crate::WordCraftApp::new(cc) ))), ); }
